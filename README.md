# Анализ капсульной эндоскопии: исследовательский проект

Репозиторий содержит модели для покадрового анализа записей капсульной
эндоскопии. Основное действующее направление — две независимые многометочные
модели Galar:

- **Anatomy** определяет анатомические ориентиры и отделы желудочно-кишечного
  тракта;
- **Pathology** оценивает наличие патологических находок.

> Это исследовательский прототип. Оценки моделей не являются диагнозом и не
> предназначены для принятия медицинских решений без проверки врачом.

## Состояние проекта

| Часть проекта | Состояние | Где находится |
|---|---|---|
| Двухмодельная система Galar | Действующее направление | `galar_dual_model/` |
| Покадровая обработка видео | Реализована как служебные команды | `galar_dual_model/tools/` |
| Локальное веб-приложение | Требования подготовлены, программная часть ещё не создана | `web_demo/AGENTS.md` |
| Прежняя 14-классовая модель Kvasir-Capsule | Сохранена как самостоятельная проверенная линия | `train.py` и `runs/` |
| Временная модель и объединение кадров в события | Запланированы, но не реализованы | `docs/PROJECT_VISION.md` |

Две модели Galar анализируют отдельные кадры. Они не учитывают соседние кадры,
не формируют клинические события и не подтверждают отсутствие заболевания, если
ни одна оценка не достигла порога.

## Проверенное окружение

Основная рабочая система:

- Windows;
- Python 3.14.2;
- PyTorch 2.13.0 с CUDA 13.0;
- NVIDIA RTX 3060, 12 ГБ видеопамяти;
- `.venv-win` как локальное виртуальное окружение.

Создание нового окружения в PowerShell:

```powershell
py -3.14 -m venv .venv-win
.\.venv-win\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install --retries 20 --timeout 120 -r requirements-cuda.txt
```

На Windows для обучения и загрузки данных используйте `--workers 0`, если
конкретная команда явно не проверена с несколькими рабочими процессами.

## Действующая двухмодельная система

### Anatomy

Модель выдаёт девять независимых sigmoid-оценок:

- анатомические ориентиры: `z-line`, `pylorus`, `ampulla of vater`,
  `ileocecal valve`;
- отделы: `mouth`, `esophagus`, `stomach`, `small intestine`, `colon`.

Одновременно могут быть верны отдел и ориентир, поэтому превращать выходы в
softmax и оставлять только одну метку нельзя.

Выбранная локальная контрольная точка:

```text
galar_dual_model/runs/anatomy_workers0_20260907/best.pt
```

Она выбрана на эпохе 10 по макро-F1 `0.399281` на проверочных исследованиях,
которые целиком отсутствовали в обучающей части. Редкие анатомические ориентиры
по-прежнему распознаются слабо, поэтому сводная метрика не должна скрывать
показатели отдельных меток.

### Pathology

Модель выдаёт двенадцать независимых sigmoid-оценок:

`ulcer`, `polyp`, `active bleeding`, `blood`, `erythema`, `erosion`,
`angiectasia`, `IBD`, `foreign body`, `hematin`, `cancer`,
`lymphangioectasis`.

`blood`, `active bleeding` и `hematin` — разные исходные метки. Их нельзя
объединять или автоматически преобразовывать друг в друга.

Выбранная локальная контрольная точка:

```text
galar_dual_model/runs/pathology/best.pt
```

Она выбрана на эпохе 8 по макро-F1 `0.144995` при фиксированном пороге `0.5`.
Последующие варианты функции потерь не улучшили этот результат. Качество
Pathology остаётся низким, особенно для меток, представленных единичными
исследованиями. Результат ниже порога означает только отсутствие срабатывания
модели, а не отсутствие патологии.

Подробное описание данных, обучения и ограничений находится в
[`galar_dual_model/README.md`](galar_dual_model/README.md).

## Обработка видео двумя моделями

Команда ниже читает видео, обрабатывает каждый кадр обеими моделями и создаёт
новый MP4 с наложенными исходными ключами меток и оценками:

```powershell
.\.venv-win\Scripts\python.exe -m galar_dual_model.tools.video_inference `
  --input "D:\video\study.mp4" `
  --output "D:\video\study_annotated.mp4"
```

Особенности:

- обе модели загружаются один раз;
- порядок меток и пороги проверяются по контрольным точкам;
- используется та же обработка изображения, что при проверке моделей;
- скрытого временного сглаживания нет;
- все метки, достигшие порога, сохраняются как многометочный результат;
- существующий выходной файл не перезаписывается.

Чтобы сохранить несколько кадров с наиболее высокими оценками Pathology без
надписей на изображениях:

```powershell
.\.venv-win\Scripts\python.exe -m galar_dual_model.tools.extract_pathology_frames `
  --input "D:\video\study.mp4" `
  --count 10
```

Команда создаёт отдельный каталог, изображения PNG и `report.json`. В отчёте
сохраняются все оценки и все метки, достигшие порога. Соседние почти одинаковые
кадры по возможности разделяются временным промежутком.

Для принудительной работы без CUDA добавьте `--cpu`. Полный список настроек:

```powershell
.\.venv-win\Scripts\python.exe -m galar_dual_model.tools.video_inference --help
.\.venv-win\Scripts\python.exe -m galar_dual_model.tools.extract_pathology_frames --help
```

## Обучение Galar

Обучение требует заранее подготовленных метаданных и локального хранилища
изображений. Оно не запускается автоматически.

Краткая проверка без записи контрольной точки:

```powershell
.\.venv-win\Scripts\python.exe -B .\galar_dual_model\train_anatomy.py `
  --image-cache-root "C:\Users\Maxx\Galar_256_cache" `
  --workers 0 --device cpu --batch-size 2 --dry-run --dry-run-samples 4

.\.venv-win\Scripts\python.exe -B .\galar_dual_model\train_pathology.py `
  --image-cache-root "C:\Users\Maxx\Galar_256_cache" `
  --workers 0 --device cpu --batch-size 2 --dry-run --dry-run-samples 4
```

Настоящий запуск всегда должен использовать новый пустой каталог результата.
Не перезаписывайте существующие каталоги в `galar_dual_model/runs/`.

## Прежняя 14-классовая модель

`train.py` остаётся канонической точкой входа для прежней одноклассовой задачи
Kvasir-Capsule. Она использует softmax и не должна смешиваться с двумя
многометочными Galar-моделями.

Проверка без полного обучения:

```powershell
.\.venv-win\Scripts\python.exe train.py --dry-run --output "runs\audit"
```

Исторически лучший вариант этой линии —
`runs/combined_galar_head_only/best.pt`. Подробные показатели и ограничения
перенесены в
[`docs/legacy/BEST_MODEL_DIAGNOSTICS.md`](docs/legacy/BEST_MODEL_DIAGNOSTICS.md).
Правила прежнего объединения внешних данных находятся в
[`docs/legacy/EXTERNAL_DATASETS.md`](docs/legacy/EXTERNAL_DATASETS.md).
Вспомогательные программы этого направления собраны в
[`legacy_14_class/`](legacy_14_class/README.md).

Эта линия сохранена для воспроизводимости и сравнения. Она не является
контрольной точкой по умолчанию для нового двухмодельного веб-приложения.

## Правила данных и оценки

- Разделение выполняется только по целым исследованиям или видео.
- Соседние кадры одного источника не могут одновременно находиться в обучающей
  и проверочной частях.
- Основная метрика выбора — макро-F1 по поддержанным меткам на невиданных
  исследованиях.
- Диагностическая настройка порогов на той же проверочной части не используется
  для выбора контрольной точки.
- Новые загруженные видео, извлечённые кадры, исходные наборы данных и рабочие
  веса моделей не отправляются в Git. Уже сохранённые контрольные точки прежней
  линии в корневом `runs/` оставлены как воспроизводимые исторические результаты.
- Оценки sigmoid и softmax называются оценками модели, а не вероятностями
  диагноза.
