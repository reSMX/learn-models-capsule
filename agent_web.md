# Задача агенту: локальный веб-MVP для демонстрации модели

## Цель

Сделать в этом репозитории локальный демонстрационный сайт, который реально загружает текущую
модель EfficientNet-B0 и показывает её работу на кадре или коротком видео капсульной эндоскопии.
Сайт нужен для презентации MVP, а не для клинического применения.

Перед началом работы полностью прочитай `AGENTS.md`, `README.md`, релевантные части `train.py` и
файлы из `runs/combined_galar_head_only`. Не запускай обучение и не изменяй датасеты.

## Текущее состояние модели

- Checkpoint: `runs/combined_galar_head_only/best.pt`.
- Архитектура: `torchvision.models.efficientnet_b0`, 14 выходных классов.
- Лучший checkpoint: эпоха 6.
- Метрика выбора: macro-F1 на video-level validation — `0.30218095314077376`.
- Общая accuracy — `0.8015190996285413`, но она сильно зависит от дисбаланса классов и не должна
  подаваться как главный показатель качества.
- Порядок классов хранится внутри checkpoint в поле `classes`; не задавай индексы классов вручную.
- Полный validation-отчёт находится в `runs/combined_galar_head_only/report.json`.
- Модель классифицирует отдельные кадры. Temporal-модель и распознавание клинических событий ещё
  не реализованы.
- На машине проверена CUDA: RTX 3060 12 GB. Сайт также обязан работать на CPU.

Checkpoint содержит словарь с ключами `model`, `classes`, `epoch`,
`val_supported_macro_f1`, `unsupported_validation_classes` и `training_config`.

Точная preprocessing-цепочка для inference должна совпадать с validation-преобразованием из
`train.py`:

1. преобразование изображения в RGB;
2. `Resize(256)`;
3. `CenterCrop(224)`;
4. перевод в `float32` с масштабированием в диапазон `[0, 1]`;
5. нормализация через `mean` и `std` от `EfficientNet_B0_Weights.DEFAULT.transforms()`.

Нельзя использовать тренировочные случайные crop, flip, rotation, jitter и random erasing во
время inference.

## Обязательный объём MVP

### 1. Структура приложения

Создай изолированный модуль, например:

```text
web_demo/
  __init__.py
  app.py
  inference.py
  labels.py
  templates/
    index.html
  static/
    app.js
    styles.css
  tests/
    test_inference.py
    test_api.py
requirements-web.txt
```

Используй FastAPI, Jinja2 и обычный HTML/CSS/JavaScript. React, Node.js, база данных, авторизация,
Docker и облачный деплой для этого MVP не нужны. Не добавляй внешнюю аналитику, CDN и сетевые
зависимости во время работы сайта.

Добавь зависимости веб-части в отдельный `requirements-web.txt`, не ломая существующие файлы
зависимостей обучения. Ожидаемые зависимости: FastAPI, Uvicorn, Jinja2, python-multipart и средство
чтения видео, если оно действительно требуется реализацией.

### 2. Сервис inference

Реализуй отдельный класс или сервис, который:

- принимает путь checkpoint через переменную окружения `MODEL_PATH`, по умолчанию использует
  `runs/combined_galar_head_only/best.pt` относительно корня репозитория;
- выбирает устройство через `DEVICE=auto|cuda|cpu`, где `auto` использует CUDA при её доступности;
- загружает checkpoint только один раз при запуске приложения;
- создаёт `efficientnet_b0(weights=None)`, устанавливает dropout из `training_config`, заменяет
  последний linear-слой на число классов и загружает `checkpoint["model"]`;
- проверяет, что индексы из `checkpoint["classes"]` уникальны, непрерывны и соответствуют размеру
  выходного слоя;
- вызывает `model.eval()` и выполняет inference внутри `torch.inference_mode()`;
- на CUDA использует autocast, если он проходит корректно, но всегда имеет безопасный CPU fallback;
- возвращает softmax для всех 14 классов, top-3, устройство и время inference;
- сериализует обычные Python `float`/`int`, а не NumPy- или Torch-типы;
- не загружает checkpoint заново на каждый запрос и не создаёт несколько копий модели в VRAM;
- ограничивает одновременный доступ к модели, чтобы параллельные запросы не вызвали OOM.

Используй безопасную загрузку checkpoint для доверенного локального файла и явный `map_location`.
При отсутствии или несовместимости checkpoint приложение должно завершать запуск с понятной
ошибкой, содержащей проверенный путь, а не показывать пользователю пустой результат.

Не импортируй `train.py` так, чтобы запуск веб-приложения мог начать подготовку данных или
обучение. Общую preprocessing-логику можно вынести в небольшой безопасный модуль, только если это
не меняет поведение канонического training pipeline.

### 3. API

Минимальные маршруты:

- `GET /` — страница приложения;
- `GET /api/health` — статус `ready`, выбранное устройство, CUDA availability и имя checkpoint;
- `GET /api/model` — эпоха checkpoint, validation macro-F1, список классов и доступные честные
  метрики из `report.json`;
- `POST /api/predict-image` — inference одного изображения;
- `POST /api/predict-video` — анализ короткого видео по равномерно выбранным кадрам.

Ответ `predict-image` должен иметь стабильную структуру примерно такого вида:

```json
{
  "top_prediction": {
    "class_key": "polyp",
    "display_name": "Полип",
    "score": 0.81
  },
  "top_predictions": [],
  "all_scores": {},
  "model": {
    "checkpoint_epoch": 6,
    "device": "cuda"
  },
  "inference_ms": 12.4
}
```

Поле `score` в интерфейсе называй «оценка модели», а не «вероятность диагноза»: softmax модели не
калиброван как клиническая вероятность.

### 4. Загрузка и проверка изображения

- Поддержи JPEG, PNG и WebP.
- Ограничь размер файла разумным значением, например 15 MB, и количество декодированных пикселей,
  например 40 мегапикселями.
- Проверяй реальное содержимое через Pillow, а не только расширение или MIME type.
- Учитывай EXIF orientation и всегда преобразовывай изображение в RGB.
- Повреждённый, пустой, слишком большой или неподдерживаемый файл должен давать понятный ответ
  `4xx`, а не traceback или `500`.
- Загруженный файл не должен сохраняться после запроса и не должен попадать в логи.

### 5. Анализ короткого видео

Видео — демонстрационная обёртка над frame-классификатором, а не temporal inference.

- Поддержи хотя бы MP4; остальные форматы добавляй только если библиотека уверенно их декодирует.
- Введи ограничения на размер и длительность, чтобы пользователь случайно не отправил
  многочасовую запись. Значения вынеси в конфигурацию и покажи рядом с формой.
- Выбирай кадры равномерно по времени. По умолчанию достаточно 1 кадра в секунду и не более 120
  кадров за один запрос.
- Обрабатывай выбранные кадры батчами, чтобы эффективно использовать GPU, но не выходить за 12 GB
  VRAM. Размер батча должен настраиваться переменной окружения.
- Временный видеофайл создавай через безопасный временный каталог и всегда удаляй в `finally`, в
  том числе при ошибке декодирования.
- Верни длительность, число выбранных кадров, timestamps, top-3 каждого кадра и общую длительность
  обработки.
- Для интерфейса можно вернуть не более 12 уменьшенных JPEG-превью самых заметных кадров. Не
  возвращай base64 для всех 120 кадров.
- Не объединяй последовательные кадры в «клинические события» и не применяй скрытое temporal
  сглаживание: такой модели в проекте пока нет.

Если надёжный video endpoint заметно задерживает завершение работы, сначала полностью закончи и
проверь сценарий одного изображения. Однако готовым MVP считается версия, в которой короткое MP4
тоже успешно анализируется.

### 7. Интерфейс

Сделай аккуратную адаптивную одностраничную страницу на русском языке:

- заголовок наподобие «Демонстрация анализа кадров капсульной эндоскопии»;
- переключатель «Изображение / Видео»;
- drag-and-drop область и обычная кнопка выбора файла;
- локальный preview выбранного файла;
- явно видимые состояния: файл выбран, анализируется, результат, ошибка;
- блок главного результата с названием класса, категорией и оценкой модели;
- горизонтальные полосы top-3 с процентами;
- раскрываемый список оценок всех 14 классов;
- для видео — компактная timeline/таблица с timestamp и результатом каждого выбранного кадра,
  фильтр по классу и галерея максимум из 12 ключевых кадров;
- небольшой блок «О модели» с эпохой checkpoint, macro-F1 и ссылкой/раскрытием подробных метрик;
- индикатор фактически выбранного устройства CPU/CUDA и времени обработки;
- кнопка сброса, позволяющая сразу провести следующую демонстрацию.

Не используй псевдомедицинские изображения, выдуманные отзывы, карты пациентов или неработающие
элементы интерфейса. Не встраивай изображения из локального датасета в Git. При необходимости
добавь опциональную переменную `DEMO_SAMPLES_DIR`: если локальная папка отсутствует, блок примеров
просто не отображается.

Интерфейс должен быть читаемым на ноутбуке и телефоне, поддерживать управление клавиатурой,
видимый focus state, достаточный контраст и `prefers-reduced-motion`. Не перегружай MVP сложными
анимациями.

### 8. Обязательные медицинские оговорки

На странице постоянно должен быть заметен текст по смыслу:

> Исследовательский прототип. Результат не является диагнозом и не предназначен для принятия
> медицинских решений без проверки врачом.

Рядом с результатом дополнительно укажи:

- модель анализирует отдельные кадры и не учитывает temporal-контекст;
- оценка softmax не является откалиброванной клинической вероятностью;
- некоторые классы распознаются заметно хуже других;
- загруженные файлы обрабатываются локально и не сохраняются.

Не скрывай слабые классы. Панель метрик должна читать данные из `report.json` и показывать
per-class precision/recall/F1, включая нулевые значения. Accuracy не должна визуально доминировать
над macro-F1.

### 9. Безопасность и устойчивость MVP

- По умолчанию сервер слушает только `127.0.0.1`.
- Не включай открытый CORS без необходимости.
- Не доверяй исходному имени файла и не составляй из него путь.
- Не оставляй временные файлы после успешного или неуспешного запроса.
- Не выводи абсолютные локальные пути пользователю, кроме серверной ошибки запуска для владельца.
- Ограничь одновременный inference; при занятости лучше вернуть понятный статус, чем исчерпать VRAM.
- Не добавляй телеметрию и не отправляй кадры во внешние сервисы.
- Не запускай несколько Uvicorn workers с одной CUDA-моделью. Для локального MVP нужен один
  процесс.

## Тесты

Добавь автоматические тесты минимум для следующих случаев:

1. загрузка checkpoint на CPU и получение ровно 14 конечных scores;
2. сумма softmax близка к `1.0`, top-3 отсортирован по убыванию;
3. preprocessing создаёт tensor формы `3 x 224 x 224`;
4. корректные PNG/JPEG проходят API;
5. текстовый файл под видом изображения, пустой файл и слишком большой запрос отклоняются;
6. отсутствующий checkpoint даёт понятную ошибку запуска;
7. API-тесты не требуют CUDA и используют mock inference там, где полная модель не нужна;
8. короткий тестовый ролик проходит video endpoint, а временный файл удаляется;
9. `GET /api/health` и `GET /api/model` возвращают документированную схему.

Проведи ручной smoke test на CPU и, если CUDA доступна, на CUDA. Не запускай обучение в рамках
тестирования. Зафиксируй фактическое время inference одного кадра и короткого ролика в итоговом
отчёте без обещаний производительности на другом оборудовании.

## Документация запуска

Обнови `README.md` отдельным разделом с командами PowerShell. Ожидаемый сценарий:

```powershell
.\.venv-win\Scripts\python.exe -m pip install -r requirements-web.txt
.\.venv-win\Scripts\python.exe -m uvicorn web_demo.app:app --host 127.0.0.1 --port 8000
```

После запуска сайт должен открываться по адресу `http://127.0.0.1:8000` без доступа к датасетам
`D:\dataset_quazir` и `D:\Dataset_galar`: для inference нужен только checkpoint.

Опиши переменные окружения `MODEL_PATH`, `DEVICE`, лимиты загрузки, частоту выборки видео и batch
size. Добавь раздел с типичными ошибками: checkpoint не найден, CUDA недоступна, неподдерживаемый
кодек видео и превышен размер файла.

## Критерии готовности

Работа считается завершённой, когда:

- сайт запускается одной документированной командой в `.venv-win`;
- checkpoint загружается один раз, а health endpoint показывает корректную эпоху и устройство;
- пользователь может загрузить изображение и увидеть настоящий top-3 модели;
- пользователь может загрузить короткий MP4 и увидеть результаты выбранных кадров по времени;
- CPU fallback реально проверен;
- ошибки файлов отображаются в интерфейсе без падения сервера;
- после запросов не остаются загруженные или временные файлы;
- на странице честно показаны ограничения модели и validation-метрики;
- тесты проходят и команды их запуска внесены в README;
- обучение не запускалось, checkpoint и датасеты не изменялись.
